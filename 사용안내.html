케어브릿지 시작 안내

메모 작성 → 재질문 답변 → 내용 확인 → 담당자 전달 → 검토·확정

1. 처음 한 번만 설정하기

  1. 바탕화면의 케어브릿지 실행을 두 번 클릭합니다. 실행 준비 후 브라우저가 열립니다.
  2. 처음에는 처음 시작하기 화면이 나옵니다. 본인이 사용할 관리자 이름·아이디·비밀번호를 직접 입력합니다. 비밀번호는 12자 이상입니다.
  3. 만든 관리자 계정으로 로그인합니다.
  4. 직원 계정 관리에서 메모 작성자, 돌봄 담당자, 사회복지사 계정을 각각 만듭니다. 서로 다른 아이디와 비밀번호를 지정하고 사용자에게 전달하세요.
  5. 각 사용자는 로그인 후 내 계정에서 초기 비밀번호를 변경할 수 있습니다.

기존 공통 시연 비밀번호와 역할 선택 로그인은 제거했습니다. 시제품은 업무별 계정을 1개씩 지원합니다. 관리자는 계정 관리 전용이며 직원 기록을 직접 조회하지 않습니다. 기존 가상 시연 기록은 유지되고 해당 역할 계정으로 연결됩니다.

2. 매일 실행하고 종료하기

  • 케어브릿지 실행: 서버가 꺼져 있으면 백그라운드에서 켜고, 이미 실행 중이면 브라우저만 엽니다.
  • 로그아웃: 현재 브라우저의 인증을 종료합니다. 다른 계정으로 바꾸려면 로그아웃 후 다시 로그인합니다.
  • 내 계정 → 모든 기기에서 로그아웃: 해당 계정의 전체 로그인 세션을 종료합니다.
  • 케어브릿지 종료: 바탕화면 실행기가 시작한 이 앱의 서버만 종료합니다. 다른 Node 프로그램은 종료하지 않습니다. 생성 중인 요청이나 저장 작업이 끝난 뒤 종료하세요.

브라우저 창만 닫으면 서버는 계속 실행됩니다. 로그인은 최대 8시간 유지되며 서버를 종료하거나 비밀번호를 변경하면 다시 로그인해야 합니다. Windows 자동 시작은 설정하지 않았습니다.

3. 예시로 먼저 사용해 보기

  1. 작성자 계정으로 로그인하고 대상자 코드와 전달할 업무를 선택합니다.
  2. 영어 예시 체험을 눌러 메모를 확인하고, 가상 메모 확인란을 체크한 뒤 다시 체험 버튼을 누릅니다.
  3. 재질문에 답하거나 모름을 선택합니다. 답변을 반영한 뒤 내용과 담당자를 확인하고 전달합니다.
  4. 로그아웃 후 해당 담당자로 로그인합니다. 목록에서 한국어 요약과 미해결 사항을 확인합니다.
  5. 검토를 시작하여 수정 요청·확정하거나 다른 담당자에게 사유를 남겨 재전달합니다.

식사·활동·일상 돌봄은 돌봄 담당자, 생활 지원·상담·서비스 연계 및 담당 판단 필요는 사회복지사에게 전달됩니다. 전달은 앱 안에서 이루어지며 이메일·문자 알림은 없습니다. 새 기록은 새로고침으로 확인합니다.

예시 체험은 고정 질문과 고정 번역을 사용합니다. 자유 답변을 실제로 번역하는 기능은 AI를 연결해야 동작합니다. 모름은 추측으로 채우지 않고 담당자에게 표시합니다.

4. 로컬 Qwen 사용

현재 설정: Qwen3.5 4B (qwen3.5:4b-q4_K_M). 모델을 설치하고 로컬 Ollama에 연결했습니다. Ollama가 실행 중인 상태에서 케어브릿지의 AI 초안 생성을 누르세요. 처음 생성할 때는 모델을 메모리에 올리는 시간이 추가됩니다. 현재 설정은 메모를 외부 AI 서버로 보내지 않습니다. 확장 평가(4개 언어, 24개 시나리오, 48회 호출)에서 15회 요청이 차단됐고, 통과한 응답에서도 시간·언어·근거·항목 분류 오류가 발견됐습니다. 현재 모델 설정은 가상 시연용으로만 사용하세요. 전체 테스트 결과 보기. 실제 업무 품질이 검증된 상태는 아니므로 담당자가 원문·초안을 확인하세요. 예시 체험은 여전히 고정 예시이며, 실제 모델은 AI 초안 생성 버튼에서 사용합니다.

연결 오류가 나면 Windows 시작 메뉴에서 Ollama를 실행한 뒤 다시 시도하세요. 다음 표는 모델을 변경하거나 다시 설치할 때 참고하세요.

준비물해야 할 일
다국어 모델입력 언어와 한국어를 지원하는 Ollama 모델을 준비합니다. 모델명만 적는 것으로 설치되지는 않습니다.
실행 환경선택한 모델의 메모리·GPU 요구량과 사용 조건을 확인합니다. 현재 설치된 qwen2.5:0.5b는 번역 오류가 확인되어 기본 연결하지 않았습니다.
설정 파일이 안내 파일과 같은 폴더의 .env.example을 .env로 복사하고 아래 항목을 채웁니다.
검증 자료실제 개인정보가 없는 메모·정답 번역·모호한 표현·모름 사례를 마련하고 두 언어를 아는 사람이 결과를 확인합니다.
PORT=3100
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=실제로 설치한 모델명

Ollama를 실행한 뒤 케어브릿지를 종료하고 다시 실행합니다. 작성자 화면에서 AI 초안 생성을 누릅니다. 모델이 없거나 응답 검사를 통과하지 못하면 오류가 표시됩니다. 화면의 ‘AI 설정 있음’은 품질 검증 완료를 뜻하지 않습니다. 외부 주소를 넣으면 메모가 그 서버로 전송됩니다.

5. 데이터와 계정 보관

  • data/notes.json: 메모 원문·질문·답변·초안·확정 내용·이력.
  • data/accounts.json: 계정 정보와 일방향 해시로 저장된 비밀번호. 평문 비밀번호는 저장하지 않습니다.
  • 백업은 서버를 종료한 뒤 data 폴더 전체를 안전한 위치에 복사합니다. 계정과 기록이 연결되므로 함께 보관하세요.
  • 아이디·비밀번호는 별도 안전한 비밀번호 관리 도구에 보관하세요. 이메일 복구·관리자 비밀번호 초기화 화면은 아직 없습니다. 잊었을 때 데이터 파일을 삭제하지 말고 복구 작업을 요청하세요.

현재는 같은 PC에서 사용하는 시제품입니다. 실제 이용자 정보, 기관 운영, 다른 PC·휴대폰 접속에는 대상자별 접근 권한, HTTPS, 직원 계정 확장, 개인정보 처리·보관·삭제 기준 등을 추가로 준비해야 합니다.

6. 화면이 열리지 않을 때

  • 실행 아이콘을 다시 눌러 봅니다. 일반 주소는 http://127.0.0.1:3100/입니다.
  • 포트 사용 중 안내가 나오면 기존 케어브릿지나 같은 포트를 사용하는 프로그램을 먼저 종료합니다. 다른 프로그램을 자동으로 종료하지 않습니다.
  • logs/server-error.log에서 오류를 확인합니다. Node.js는 22 이상이어야 합니다.
  • 바로가기 대상이 없다는 메시지가 나오면 앱 폴더를 이동했는지 확인합니다. 폴더를 이동한 경우 바로가기를 다시 만들어야 합니다.

7. 사회복지사·돌봄 담당자 채팅 도구

담당자 계정으로 로그인하면 상단에 채팅 도구가 표시됩니다. 본인에게 전달된 기록만 조회·처리할 수 있습니다. 자연스러운 표현은 로컬 Qwen이 의도를 분류하고, 실제 작업은 서버의 권한·상태 규칙으로 수행합니다. 기록 내용은 요청 분류 모델에 넣지 않습니다.

  1. 받은 기록 보여줘 → 목록에서 번호 확인.
  2. 1번 열어줘 → 요약·미해결 사항·원문 열람.
  3. 이 기록 검토 시작 → 대상과 변경 내용을 확인하고 실행 입력.
  4. 이 기록 수정 요청, 사유: 관찰 시점과 식사량 확인 → 제안 확인 후 실행.
  5. 이 기록 재배정, 담당: 돌봄, 사유: 일상 돌봄 확인 → 제안 확인 후 실행. 사회복지사에게 보낼 때는 담당: 사회복지사.
  6. 최종 확정은 아래처럼 직접 작성합니다. 원문과 최종 내용을 확인한 뒤 원문 확인 완료 실행을 입력합니다.
확정
기록: 직접 확인한 최종 기록 내용
의견: 검토 의견

검색 식비 / 대기 기록 / 미해결 기록 / 검토 중 기록 / 확정 기록 / 도움말도 사용할 수 있습니다. 취소를 입력하면 제안을 폐기합니다. 제안은 5분 후 만료되며, 새 요청을 보내면 이전 제안은 취소됩니다. 기록이 다른 화면에서 바뀌면 다시 확인해야 합니다.

현재 열어둔 기록이 작업 대상입니다. 실행 전 대상 코드·기록 번호·초안을 확인하세요. 재배정하면 이전 담당자는 해당 기록을 더 이상 열 수 없습니다. 채팅 표시 내용은 화면을 새로고치거나 로그아웃하면 사라지지만 실제 처리 결과와 처리 이력은 기록에 남습니다. 모델 해석 실패 시 안내된 고정 명령을 사용할 수 있습니다. 삭제·외부 메시지 발송·진단 기능은 지원하지 않습니다.
